# Belde implementation contracts

Godot4.6.3 compatibility renderer, desktop1440x900 responsive canvas. Gameplay map32x20 tiles,32px each, render rect(352,132,1024,640). All positions in simulation are tile-space Vector2 internally; snapshot JSON uses [x,y]. Source preproduction is retained unchanged. New runtime JSON lives game/data. Main app and renderer owned by parent; other scripts own isolated responsibilities.

## Catalog (scripts/catalog.gd)
`extends RefCounted`, `class_name BeldeCatalog`. `_init()` loads game/data/characters.json,world.json,abilities.json,story.json. Fields `characters:Array`, `by_id:Dictionary`, `world:Dictionary`, `abilities:Dictionary`. `get_character(id:String)->Dictionary`, `get_ability(id:String,slot:int)->Dictionary`, `candidates(origin:String)->Array`. Canonical origins Bar,Kingdom,Village,Royal Capital,Prison,Monster General. Slot0/1 internally. Stats nested basic_attack. Runtime ability effects must be explicit data, never parse prose during combat.

## Campaign (scripts/campaign.gd)
`extends RefCounted`, `class_name BeldeCampaign`; `_init(catalog=null)`. Fields `act:int=1`, `stage:String` (title/origin/recruit/story/battle/generals/reinforce/ending), `party:Array` (character ID strings), `fallen:Array`, `flags:Dictionary`, `history:Array`, `origin:String`, `recruit_limit:int`, `selected:Array`.
Methods `new_run(origin:String)`, `recruit(id:String)->Dictionary`, `confirm_recruits()->Dictionary`, `battle_finished(won:bool,surviving_ids:Array)->Dictionary`, `choose_story(choice_id:String)->Dictionary`, `snapshot()->Dictionary`, `restore(data:Dictionary)->Dictionary`, `current_map_id()->String`, `available_candidates()->Array`, `ending(forgive:bool)->Dictionary`.
Default act flow: originchoice=>recruit2=>MAP01/ActI=>MAP02/ActII=>winchoose2generals/lossskip=>MAP03/ActIII=>capital/prisonreinforce5iflossor<=1originalsurvivedelse3=>MAP04/ActIV(optional recovery battle)=>MAP05andMAP06/ActV=>forgive/refuseending. Casualties persist; explicit restart/newrun available. Both losses and wins progress; no softlocks.

## Simulation (scripts/simulation.gd)
`extends RefCounted`, `class_name BeldeSimulation`, `_init(catalog=null)`.
Fields `units:Array`, `enemies:Array`, `towers:Array`, `traps:Array`, `effects:Array`, `projectiles:Array`, `phase:String` (planning/combat/victory/defeat), `map:Dictionary`, `wave:int`, `max_waves:int`, `coins:int`, `gate_hp:float`, `gate_max_hp:float`, `revision:int`, `events:Array`, `speed:float`.
Methods `setup(map_data:Dictionary,party_ids:Array,difficulty:float=1.0,enemy_hp_multiplier:float=1.0)`, `step(delta:float)`, `start_wave()->Dictionary`, `command(cmd:Dictionary)->Dictionary`, `snapshot()->Dictionary`, `restore(data:Dictionary)->Dictionary`, `survivors()->Array`. Difficulty controls swarm counts; the separate health multiplier affects new spawns. Story fortifications increase gate capacity from 100, bounded at 200. Battle saves retain both values with backward-compatible defaults.
Commands use `kind`: place_unit{id,cell:[x,y],mode:Guard|Patrol|Advance}, move_unit{uid,cell}, set_mode{uid,mode}, cast{uid,slot:0|1}, place_tower{tower_id,cell}, upgrade_tower{uid}, place_trap{trap_id,cell}, set_track{points:[[x,y],...],track_id}, undo,redo. Layout edits planning only. Casts combat only. Results {ok:bool,message:String,revision:int}. IDs uid stable. Entity fields id,uid,pos:Vector2,hp,max_hp,state,mode,cooldowns:Array,attack_timer,range. Enemies hostile/surrendered/noncombatant distinguish; no attacks on nonhostiles. Effects pos,kind,ttl,color, optionaltarget; projectiles from/to/pos dictionaries. Snapshot is recursively JSON-safe. Track validation forbids disconnected jumps,occupiedoutofbounds cells,blocking enemy lanes; history records full layout and economy, preserves roster/coins. Revision only changes authored layout.

## Local bridge (scripts/local_bridge.gd)
`extends Node`, `class_name BeldeLocalBridge`; `configure(state_provider:Callable,command_handler:Callable,port:int=43127)->Error`, `pairing_code:String`, `editor_connected:bool`, `shutdown()`.
HTTP loopback127.0.0.1 only. `/health` unauth no game data; unified `POST /native` takes JSON{op:pair|state|command|heartbeat|disconnect,code?,token?,client_id?,command?,expected_revision?}. Native host forwards frames exactly; app callbacks return dictionaries. Pair grants cryptorandom token for one editor client,ttl15sec refreshedheartbeat. State/command requiretoken. Freshsecondclient=>409 exact session warning. BrowserOrigin disallowed/no CORS. Capbodies64KiB,conns/timeouts. Godotportexclusive rejects secondPCinstance; expiry releases editor lease. State snapshot includes campaign,simulation,revision,connection info.
Parent queues safe layout edits during combat and applies in planning; conflicting expected_revision returns rejection; bridge must propagate response errors.

## Art runtime
`assets/actors/manifest.json` declares each ID's file, row, rows, eight columns and frames: idle 0, walk_a 1, walk_b 2, run 3, attack 4, ability_a 5, ability_b 6, downed 7. Explicit row bounds avoid assuming equal vertical spacing. `idle_bounds_px` anchors the feet and preserves aspect ratio; allied ink height is 52px, most monsters 39px, and the boss 95px. `effect_only_frames` retains an idle body underneath the listed effects. Portraits use AtlasTexture regions from copied preproduction boards. These are prototype key poses; see `docs/ART-REVIEW.md` for coverage and remaining art work.

## Application and validation
`main.gd` owns scene navigation, saves, pause/settings, commands and the combat-edit queue. `battle_view.gd` renders the authoritative simulation; it does not decide damage. `art.gd` loads/caches atlas regions; `audio.gd` supplies generated cues and accompaniment. `local_bridge.gd` owns local pairing; `global_session.gd` optionally connects to a separately configured profile coordinator.

`tools/run_checks.py` tests campaign, combat, actual scene callbacks, native framing, the loopback bridge and the optional coordinator. Additional editor/transport integration checks live in `tests/`. `docs/BUILD.md` explains exports and platform validation. Headless tests do not establish graphical quality or real mouse behavior.
